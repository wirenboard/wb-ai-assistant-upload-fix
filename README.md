# wb-ai-assistant-upload-fix

Плагин Discourse: не отдаёт модели вложения, привязанные к постам ИИ-бота. Без этого один такой
пост ломает диалог с ботом навсегда.

## Что за поломка

Бот ставит в своём ответе ссылку на присланный клиентом файл — `[паспорт](upload://…pdf)`. Discourse
по этой ссылке привязывает вложение к посту **бота**. Дальше Discourse AI складывает в сообщение
истории вложения того поста, из которого оно собрано, поэтому файл уезжает в сообщении с ролью
`assistant`. Responses API разрешает там только `output_text` и `refusal` и отвергает запрос целиком:

```
Invalid value: 'input_file'. Supported values are: 'output_text' and 'refusal'.  (HTTP 400)
```

**Поломка необратима сама по себе:** пост остаётся в истории, поэтому отваливаются не один ответ, а
все последующие. Клиент видит «Sorry, it looks like our system encountered an unexpected issue» с
английской технической вставкой и больше не получает ответов в этой теме.

Живой случай: тема поддержки простояла двое суток, девять попыток ответа подряд — все 400. Правка
постов руками помогает, но ненадолго: модель ставит такую ссылку снова в следующем же ответе.

## Как работает

- Перехват `DiscourseAi::Completions::PromptMessagesBuilder#push` — через него проходят все
  сообщения истории, и у сообщений типа `:model` убираются вложения: и список `upload_ids`, и уже
  готовые части `{ upload_id: … }` внутри содержимого.
- Клиентские вложения не трогаются: они остаются в своих, пользовательских сообщениях. В тексте
  ответа бот файл и так называет словами, так что модель не теряет контекст.
- Побочная польза: один и тот же файл больше не уезжает в запрос дважды — на длинных документах это
  заметная экономия.
- Каждый случай пишется в `production.log`:
  `[wb-ai-assistant-upload-fix] вложений убрано из хода ассистента: N`.

## Настройки (Админка → Настройки → Плагины)

| настройка | по умолчанию | смысл |
|---|---|---|
| `wb_ai_assistant_upload_fix_enabled` | включено | выключатель; выключать только для проверки |

## Проверка

`spec/` — 7 примеров на Discourse 2026.7.1 и 2026.8.0: вложения клиента остаются, вложения бота
убираются (и списком, и частями внутри содержимого), сообщение бота без текста не превращается в
пустой массив, с выключенной настройкой поведение прежнее, плюс сквозная сборка истории из настоящей
переписки, где один файл привязан и к вопросу клиента, и к ответу бота. Мутации ловятся: без снятия
`upload_ids` падают 2 примера, без чистки содержимого — 2, без проверки типа сообщения — 3.

Это обход дефекта самого Discourse AI: вложения постов ассистента там не фильтруются. Правку стоит
предложить в upstream, после чего плагин станет не нужен.

Установка на прод — строкой `git clone` в `app.yml` и перезапуском unicorn, как у других плагинов WB.
